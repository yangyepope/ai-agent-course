# 一、谁负责什么

| 环节 | 谁负责 | 在哪跑 |
|---|---|---|
| 文档解析 | ⚠️ 本课无 | — |
| 切片 | ⚠️ 本课无，`documents.json` 手写 | 第 9 课的活 |
| **向量计算** | `embedding.py` | Python 进程，本机 CPU/GPU |
| **存 + 检索** | Elasticsearch | 独立进程 :9200，不做模型计算 |
| LLM 生成 | ⚠️ 本课无 | — |

# 二、离线：把数据灌进去（跑一次）

```
documents.json          手写的 4 个 chunk
      │
      ↓  init_index.py
index_manager.py        建索引：content=text, embedding=dense_vector(512)
      │
      ↓  index_documents.py
document_service.py     读文件，抽出 content
      │
      ↓
embedding.py            ★算向量★  文字 → 512 维
      │
      ↓
document_service.py     文字 + 向量 拼一条，写入
      │
      ↓
Elasticsearch           文字建倒排表，向量建 HNSW 图
```

# 四、节点职责

| 节点 | 职责 |
|---|---|
| `main.py` | 应用入口，挂路由 |
| `api.py` | 收参数、整理返回 |
| `search_service.py` | 编排：先向量化，再查 ES |
| `embedding.py` | 文字 ⇄ 向量（写入/查询共用同一模型） |
| `elasticsearch_client.py` | 唯一知道 ES 地址的地方 |
| `index_manager.py` | 索引名 + 字段类型（写方读方的契约） |
| `document_service.py` | 离线灌数据 |
| Elasticsearch | 存 + filter + BM25 + kNN + RRF + 截断 |

# 五、四个为什么

```
为什么要向量化问题？   用户换个说法，纯关键词就搜不到
为什么两路一起查？     BM25 擅长专有名词，kNN 擅长换句话说，短板互补
为什么先 filter？      隔离没做好，检索再准也是数据泄漏
为什么 ES 不算向量？   向量在 Python 端算好再发过去，ES 只存和算距离
```

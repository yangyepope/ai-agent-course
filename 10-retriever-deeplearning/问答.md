# 如何通过测试集评估 Threshold

## 1. 核心思路

Threshold 是一道"相似度闸门"：

多高的分才算"足够相关"？

不能拍脑袋。

要用"已知答案"的问题集去测：

每个测试问题，都人工标注：

哪些文档真的能回答它。

然后试不同阈值。

看哪道闸门最准。

## 2. 第一步：构造带标注的测试集

从真实业务里抽 50~200 条有代表性的问题。

人工标注每条问题的正确答案在哪些文档里：

```python
test_set = [
    # (问题, 相关的文档 id 集合)
    ("出差交通费能报销吗？", {"doc_07", "doc_12"}),
    ("年假可以累计到下一年吗？", {"doc_03"}),
]
```

这一步最费人工。

但决定评估质量。

## 3. 第二步：对每个候选阈值打分

关键技巧：

Threshold 过滤发生在"拿回分数"之后。

所以只检索一次拿到全部候选分数。

再在不同阈值下分别过滤。

不需要重复向量化：

```python
import numpy as np
from app.embeddings import EmbeddingService
from app.vector_store import VectorStore

emb = EmbeddingService()
store = VectorStore(documents=documents, embedding_service=emb)
doc_id_list = [d.id for d in documents]

CANDIDATE_THRESHOLDS = [0.3, 0.4, 0.5, 0.6, 0.7, 0.8, 0.9]

per_threshold = {t: {"n": 0, "hit": 0, "precision_sum": 0.0} for t in CANDIDATE_THRESHOLDS}

for query, relevant_ids in test_set:
    # 一次检索，拿全部候选
    q_vec = np.asarray([emb.embed_query(query)], dtype="float32")
    scores, indices = store.index.search(q_vec, k=len(documents))

    for t in CANDIDATE_THRESHOLDS:
        # 模拟 threshold 过滤：分数 >= t 且不是 -1 占位
        retrieved = [
            doc_id_list[idx]
            for score, idx in zip(scores[0], indices[0])
            if idx >= 0 and float(score) >= t
        ]
        if not retrieved:
            continue  # 闸门太严，什么都没返回
        hits = set(retrieved) & relevant_ids
        per_threshold[t]["n"] += 1
        per_threshold[t]["hit"] += 1 if hits else 0
        per_threshold[t]["precision_sum"] += len(hits) / len(retrieved)

for t, m in per_threshold.items():
    if m["n"] == 0:
        print(f"threshold={t}: 所有问题都没返回结果（过严）")
        continue
    print(f"threshold={t}: 返回率={m['n']/len(test_set):.0%}, "
          f"命中率={m['hit']/m['n']:.0%}, "
          f"平均精确率={m['precision_sum']/m['n']:.2f}")
```

## 4. 第三步：挑阈值 + 二次验证

看输出表：

三个指标互相制约：

| 指标 | 含义 | threshold 调高时 |
| ---- | ---- | ---- |
| 返回率 | 有多少问题还能返回结果 | 下降（过严就全拒了） |
| 命中率 | 返回的结果里，有多少问题至少命中 1 条正确答案 | 通常上升 |
| 平均精确率 | 返回的结果里"正确/总数" | 上升（噪音被滤掉） |

按业务取舍：

- 宁可不说、不说错（答错代价高）→ 选高 threshold，牺牲返回率
- 尽量都答、别漏 → 选低 threshold
- 一般取 F1 最优，或"命中率高且返回率不塌"的点

注意：

挑出来的阈值要用另一批没参与调参的问题再验证一次。

防止"过拟合测试集"。

## 5. 两个工程注意点

1. 先看分数分布，再选候选值：

   先跑 20 条真实问题，打印分数大概在哪个区间。

   再在区间内取候选值，别盲试 0.3~0.9。

2. Threshold 和 Top-K 联动：

   企业常用"先 Top-K 粗筛，再 threshold 精过滤"。

   调 Threshold 时，K 也要一起验证。


# 思考4：
注意这里有一个非常关键的变化：

以前：

self.index.search(
    query_embedding,
    k,
)

现在：

self.index.search(
    query_embedding,
    len(self.documents),
)

为什么？

因为如果：

k = 3

但是前 3 个里面：

Doc1 finance
Doc2 hr
Doc3 technical

你过滤：

category = finance

那么可能只剩：

Doc1

所以我们先扩大候选集：

全部候选
 ↓
Metadata Filter
 ↓
Threshold
 ↓
Top K

这是非常重要的检索思想。
